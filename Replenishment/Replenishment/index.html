Replenishment Configuration & Process

Configuration Setup

Pick Location View (vPickLoc)

The core replenishment logic in vPickLoc is consistent across environments.
However, in some implementations, the view includes additional fields to support default UOM / case-level quantity calculations.

Extended Fields

In environments where enhanced replenishment visibility is required, the following fields may be available:

  • DEFAULTCURRENTQTY
  • DEFAULTPENDINGQTY
  • DEFAULTALLOCATEDQTY
  • DEFAULTOVERALLOCATEDQTY
  • DEFAULTNORMALREPLQTY
  • DEFAULTHOTREPLQTY
  • DEFAULTMAXIMUMQTY
  • DEFAULTHOTMAXREPLQTY
  • DEFAULTUOM
  • CASEQUANTITY
  • UOM

These fields are derived using UOM conversion logic (e.g., CASE vs EACH) and are used for improved display and validation.

Purpose

The vPickLoc view is responsible for:

  • Calculating current inventory
  • Calculating pending replenishment quantities
  • Identifying below-threshold locations
  • Supporting replenishment decision-making

Note

  • Base replenishment logic exists in all environments
  • Additional "DEFAULT" fields are environment-specific enhancements, not mandatory

Replenishment Policy Setup

Overview

The Replenishment Policy defines how inventory is replenished from storage locations into pick locations.

This is a functional configuration that determines:

  • Source of inventory
  • Replenishment behavior
  • Task creation logic

Policy Configuration

Each Pick Location must have a Replenishment Policy assigned.

Example:

Policy ID Policy Name
Replen1 Replen1

Key Fields

From Pick Region

This is the most critical field in the Replenishment Policy.

  • Defines the storage region from which inventory is pulled
  • Acts as the source location for replenishment

Storage Location (From Pick Region) ↓ Pick Location

  • If this value is incorrect:

  • Replenishment jobs will NOT be created

  • System will not find inventory
  • Locations will remain below threshold

Schedule Replenishment

Overview

The Schedule Replenishment screen is used to identify pick locations that require replenishment and to generate replenishment jobs.

This is the primary screen used to trigger replenishment manually.

Purpose

  • Identify locations below threshold
  • Filter locations based on replenishment criteria
  • Trigger replenishment jobs
  • Populate pending quantities
  • Generate replenishment tasks

Below Threshold Logic

The most commonly used filters are:

  • Below Threshold Normal = Yes
  • Below Threshold Hot = Yes

This returns only locations where:

  • Current quantity is below configured min level
  • Replenishment is required

Understanding Pending Quantity

  • Pending Qty = 0 → No replenishment planned
  • Pending Qty > 0 → Replenishment job already exists (planned but not completed)

Replenishment Execution

Steps to trigger replenishment:

  1. Apply filters (typically Below Threshold = Yes)
  2. Click Search
  3. Select required locations
  4. Click Replenish

Replenishment Behavior

When Replenish is clicked:

  • System searches inventory from From Pick Region
  • Validates availability of stock
  • Creates replenishment jobs
  • Updates Pending Quantity

Important Notes

  • Only locations below threshold are returned when using proper filters
  • If inventory is not available in the From Pick Region
  • No replenishment job will be created
  • Pending quantity will be updated immediately after job creation

Validation

After running replenishment:

  • Return to the grid
  • Verify Pending Quantity is updated
  • This confirms that replenishment jobs were created successfully

Replenishment Jobs

Overview

The Replenishment Jobs screen displays all replenishment jobs created by the system after running Schedule Replenishment.

Each job represents a movement of inventory from a storage location to a pick location.

Purpose

  • View all generated replenishment jobs
  • Track job status
  • Validate source and destination locations
  • Access related execution tasks

Link to Tasks

Each replenishment job generates a task.

To view the task:

  1. Click on the Replenishment ID
  2. System navigates to the Tasks screen

Important Notes

  • Jobs are created only if inventory is available in the From Pick Region
  • Multiple jobs can be created based on selected locations
  • Jobs remain in Planned status until executed

Tasks (Execution)

Overview

The Tasks screen represents the execution layer of replenishment.

Each task corresponds to a replenishment job and is executed by users (via RDT).

Purpose

  • Execute replenishment jobs
  • Assign tasks to users

Task Execution Flow

  1. Replenishment job creates task
  2. Task appears in Available status
  3. User assigns the task
  4. Task is executed via RDT
  5. Inventory is moved
  6. Task status changes to Complete
  7. Replenishment job is marked Complete

Important Notes

  • Tasks are automatically generated when Create Task = Yes in Replenishment Policy
  • If tasks are not created:
  • i)Check Replenishment Policy
  • ii)Verify inventory availability
  • Tasks are the final step in the replenishment process

Together, they complete the replenishment lifecycle from storage → pick location.
